# AGENTS.md — 指针式数据版本控制

涉及**版本化数据**的设计与开发时，本文件为强约束，必须完整遵守。

## 适用范围

- 本文件在**用户判定某业务数据采用指针式版本控制后**生效，此后必须完整遵守
- 判定前的策略选择流程见 `/backend/AGENTS.md`「Data Retention Strategy（业务数据保留策略）」
- 必须同时遵守：根目录 `/AGENTS.md` 与 `/backend/AGENTS.md`

---

## 1. 数据模型

```
<entity>（主表，聚合根）              <entity>_version（版本表，append-only 不可变）
├─ id                                ├─ id
├─ current_version_id ────指针─────→  ├─ entity_id
├─ 永不变化的字段                      ├─ version（同一实体内从 1 递增）
│  （如 created_by、归属关系）          ├─ 会变化的业务字段（完整快照）
└─ created_at / updated_at            └─ created_at
```

**字段归属规则**：

- 永不变化的字段放主表（创建者、归属关系等），查询它们无需 join
- 会变化的业务字段放版本表，每行保存该版本的**完整快照**
- 任何版本必须能靠单独一行还原全貌，禁止依赖 diff 重放

---

## 2. 写入（创建新版本）

- 首个版本 `version = 1`；此后每个新版本 `version` = 当前版本 + 1，
  版本链必须连续（v1 → v2 → v3），禁止跳号或分叉
- 写入流程（**同一事务内**完成，保证「插版本 + 移指针」原子性）：
  1. `INSERT` 版本表新行（完整业务字段快照）
  2. 更新主表指针 `current_version_id` 指向新版本
- **禁止** `UPDATE` 或 `DELETE` 任何历史版本行；版本表只允许 `INSERT`

---

## 3. 读取

- 默认读取当前版本：主表 → 指针 → 版本表（一次 join）
- **禁止**通过 `MAX(version)` 或聚合子查询判断当前版本
- 历史版本必须支持显式查询：`?version=N` 或 `version_id`
- 业务条件查询：以指针 join（`JOIN <entity> e ON e.current_version_id = v.id`）作为
  "仅当前版本"过滤器，配合版本表业务字段索引；分页排序同理

---

## 4. 并发与一致性

- 版本表约束：`UNIQUE (entity_id, version)`；`entity_id` 外键指向主表 `id`；关键字段 `NOT NULL`
- 更新指针必须乐观锁：
  `UPDATE <entity> SET current_version_id = :new WHERE id = :id AND current_version_id = :expected_old`
- 乐观锁影响行数为 0，或唯一约束冲突 → 一律返回 HTTP 409 / 业务码 `40900`（数据版本冲突）

---

## 5. 回滚（历史版本 → 新版本）

- **回滚 = 以历史版本为数据源创建一个新版本**，随后指针指向该新版本
- 回滚后 `version` 继续递增：如当前 v3 回滚到 v1 的数据 → 生成 v4（内容等于 v1）
- 历史版本保持线性、永不丢失；回滚操作本身可追溯（从哪个版本回滚、何时发生）
- **禁止**把指针直接移回旧版本；**禁止**删除或修改任何已有版本来"实现"回滚
- 回滚同样只能通过 `create_version()`（以历史版本快照为数据源）完成

---

## 6. 统一数据访问

- 只能通过 Repository 统一方法操作：`get_current()` / `get_version()` / `create_version()`
- 业务层（Service / Router）禁止自行编写版本选择、指针更新逻辑
- 各模块 Repository 的这些方法保持签名一致，便于复用与审查

---

## 7. 演进约定（需确认后启用）

- 默认纯指针 join 查询；性能优化（主表冗余当前值、搜索读模型等）必须先向用户说明
  方案并获确认，**版本表始终是唯一事实源**
- 版本表新增业务字段时，历史版本行允许 `NULL`，**禁止回填伪造历史**
- 审计字段（如 `operator` / `change_reason`）默认不含；业务有审计需求时经用户确认后添加

---

## 8. 测试要求

- 版本链完整性（v1 → v2 → v3，历史版本不丢失）
- 当前版本读取正确（指针指向最新）
- 显式历史版本查询
- 并发创建版本冲突（唯一约束 + 乐观锁触发 40900）
- 历史回滚生成新版本（version 继续递增、旧版本不变、指针指向新版本）
- 写入事务回滚（插版本失败时指针不动）
